# Безопасность БЗК Принт - сверка со старым сайтом и локальный пентест

Документ отвечает на два вопроса: перенесены ли в новый сайт меры
безопасности старого (`C:\Projects\bzk`, PHP) и что показал локальный
пентест. В конце - что доработано.

Дата: сентябрь 2026. Проверялось на локальной сборке (`localhost:3005`)
и по исходникам.

---

## 1. Перенос мер безопасности: старый сайт → новый

| Мера | Старый сайт (PHP) | Новый сайт (Next.js) | Итог |
|---|---|---|---|
| CSP (защита от XSS) | `.htaccess`, `unsafe-inline` + `unsafe-eval` для скриптов | `src/proxy.ts`, скрипты по одноразовому nonce + `strict-dynamic` | **Строже** |
| X-Frame / clickjacking | `X-Frame-Options`, CSP | `X-Frame-Options` + `frame-ancestors 'none'` | Перенесено |
| X-Content-Type-Options, Referrer-Policy, Permissions-Policy | `.htaccess` | `next.config.ts` | Перенесено |
| CSRF | вручную, `validate_csrf_token()` | серверные действия только POST + сверка Origin/Host + `SameSite` куки (встроено в Next) | Перенесено иначе |
| Ограничение частоты (rate limit) | по файлам (`_check_rate_limit_file`) | по базе, `src/lib/rate-limit.ts` | **Надёжнее** (старый аудит сам ругал файловый) |
| Безопасная загрузка файлов | `secure_file_upload()`: случайное имя, проверка mime/расширения/размера | `src/lib/uploads.ts`: то же + отдача через маршрут с проверкой владельца | Перенесено |
| Путь-обход (path traversal) | - | `uploadPath()`: `basename` + проверка префикса | **Добавлено** |
| Хеш пароля | `password_hash` (bcrypt) | `bcryptjs`, стоимость 10 | Перенесено |
| Сложность пароля | `validate_password()`: 8 симв., строчная+заглавная+цифра | **было потеряно, восстановлено** (`src/lib/password-policy.ts`) | Восстановлено |
| Токен сброса пароля | хранился в БД **в открытом виде** (старый аудит: критично) | хранится SHA-256, сравнение `timingSafeEqual` | **Исправлено** |
| Одноразовая почта при регистрации | `isDisposableEmail()`, список 60 тыс. доменов | `src/lib/email-guard.ts`, короткий список ходовых сервисов | Перенесено (компактно) |
| Ловушка от ботов | Cloudflare Turnstile (в аудите - отключена) | honeypot-поле в форме связи + rate limit | Перенесено частично |
| Настройки cookie сессии (httponly/samesite/secure) | `_bzk_init_session()` | куки Auth.js (JWT), `SameSite`, `Secure` в проде | Перенесено |
| Второй фактор (2FA) | не работал | TOTP по RFC 6238, `src/lib/totp.ts` | **Добавлено** |
| Проверка владельца (IDOR) | `api_require_ownership()` | проверки в серверных действиях и `/api/uploads/[id]` | Перенесено |
| Секрет вебхука телеграма | `verifyTelegramWebhook()` | `checkWebhookSecret()`, `timingSafeEqual`, обязателен в проде | Перенесено + усилено |
| Блокировка «подозрительных» query-строк | regex в `.htaccess` | не требуется: запросы параметризованы (Drizzle), PHP нет | Неактуально |
| SSL-верификация исходящих запросов | проверялась скриптом | стандартный `fetch`/`undici`, верификация включена | По умолчанию |

**Вывод.** Всё, что защищало старый сайт, в новом есть или сделано
надёжнее. Две вещи старый сайт делал плохо, и они исправлены: открытый
токен сброса и файловый rate limit.

## 2. Локальный пентест

Проверки выполнены против запущенной сборки. Ниже - что пробовали и что
получили.

| Проверка | Запрос | Результат |
|---|---|---|
| Заголовки безопасности | `GET /` | CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy на месте |
| Приватный файл без входа | `GET /api/uploads/1` | `401` |
| Фото брака без прав | `GET /api/qc-photo/<имя>` | `403` |
| Path traversal в выдаче картинок | `/api/product-image/..%2f..%2f.env`, `/../../../etc/passwd` | `404` (имя проверяется по образцу) |
| Админка без входа | `/admin`, `/admin/finance`, `/admin/audit`, … | `307` → `/login` |
| SQL-инъекция в списке товаров | `/api/products?ids=1);DROP TABLE users;--` | `200`, запрос параметризован, инъекции нет |
| Вебхук телеграма без секрета | `POST /api/telegram/webhook` | в проде без секрета - `503`; с настроенным секретом - `401` при несовпадении |
| Серверные действия | обход прав | каждое действие проверяет права/пользователя; проверяется `check:security` |

**Критических дыр не найдено.** Аутентификация обязательна везде, где
должна быть; приватные файлы закрыты; обход пути невозможен; запросы к
базе параметризованы.

## 3. Что доработано по итогам

1. **Сложность пароля восстановлена** (`src/lib/password-policy.ts`):
   минимум 8 символов, строчная и заглавная буквы, цифра. Проверяется при
   регистрации, смене и сбросе. Существующих паролей не касается.
2. **Отсев одноразовой почты** при регистрации (`src/lib/email-guard.ts`).
3. **Вебхук телеграма** в проде отклоняет запросы, если секрет не задан
   (раньше пустой секрет означал «пускать всех»).
4. **Промокоды** получили ограничение частоты - иначе действующие коды
   можно было вычислить перебором.
5. **Проверка Origin серверных действий** (`allowedOrigins` в
   `next.config.ts`, домен из `SITE_DOMAIN`) - второй рубеж к встроенной
   защите Next.
6. **Предел размера тела** серверных действий и прокси поднят до 55 МБ:
   иначе загрузка макета до 50 МБ молча обрывалась на 1 МБ (заодно
   закрыт баг загрузки).
7. **Проверочный скрипт `check:security`** - стережёт всё перечисленное:
   сложность пароля, отсев почты, охрану серверных действий, набор
   заголовков и CSP, безопасное сравнение секретов.

## 4. Осознанно не сделано

- **Cloudflare Turnstile / капча на входе и регистрации.** На старом
  сайте капча была, но по его же аудиту - отключена. Сейчас вход и
  регистрацию защищают ограничение частоты и honeypot. Вернуть капчу
  можно: нужны ключи Turnstile и строка в CSP (`challenges.cloudflare.com`).
- **Полный список одноразовых доменов (60 тыс.).** Компактный список
  закрывает почти весь спам, не раздувая бандл. При необходимости -
  подгрузка полного списка из файла на сервере.
- **Инвалидация всех сессий при смене пароля.** Сессия в JWT живёт до 30
  дней; смена пароля не выкидывает старые сессии на других устройствах.
  Для этого нужна колонка-версия токена - отдельная задача.
