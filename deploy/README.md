# Скрипты развёртывания

Боевой сайт работает в Docker Compose за Caddy. Порядок и назначение
скриптов - ниже. Подробная инструкция с нуля - в `../DEPLOY.md`.

## Порядок при установке с нуля

1. **`setup-server.sh`** - на голом сервере Ubuntu LTS, `sudo bash`.
   Обновляет систему, ставит Docker, Node, UFW, Fail2ban, swap, часовой
   пояс, готовит `/opt/bzk-app`. Запускается один раз.
2. Скопировать код в `/opt/bzk-app`, создать `.env` из
   `../.env.production.example`.
3. **`first-install.sh`** - из корня проекта. Проверяет `.env`, вызывает
   `deploy.sh`, наполняет базу (права, реквизиты), заводит администратора.

## Повседневное

| Скрипт | Что делает |
|---|---|
| `deploy.sh` | Выкладка новой версии: страховочный дамп `backups/pre-deploy-….dump` (хранятся 10 последних), сборка образа, `drizzle-kit push`, перезапуск, ожидание статуса `healthy` у healthcheck контейнера `app`. Основная команда обновления. |
| `backup-now.sh` | Ручной полный бэкап: дамп базы (`.dump`, формат custom, с проверкой) + архив файлов в `backups/manual-…`. |
| `restore.sh` | Восстановление из бэкапа (интерактивный выбор даты или путь аргументом). Понимает `.dump` (формат custom: ночные, ручные, перед деплоем) и `.sql.gz` (копии до перехода на custom). Идёт одной транзакцией: сбой посередине оставляет базу как была. |
| `status.sh` | Статус контейнеров и healthcheck приложения, ответ `/api/health` (только `ok`/`degraded` - подробности сбоя в логе приложения), память, размер базы, свежие бэкапы. |
| `restart.sh` | Перезапуск приложения (`restart.sh all` - всех сервисов). |
| `logs.sh` | Логи приложения. |

## Вспомогательное

- **`compose.tools.yml`** - служебный контейнер `tools` (стадия `builder`
  образа) для миграций схемы и seed-скриптов. Боевой образ standalone и
  этого не умеет. Подключается вторым `-f` к `docker-compose.yml`.

## Не используется

- **`systemd/`** (`bzk.service`, `nginx.conf`) - альтернативный вариант
  запуска на голом узле без Docker (systemd + nginx). Текущее
  развёртывание идёт через Docker Compose и Caddy, поэтому эти файлы не
  задействованы. Оставлены на случай переезда на bare-metal; при работе
  по инструкции их трогать не нужно.
