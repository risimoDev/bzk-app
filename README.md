# БЗК Принт

Сайт рекламно-производственного агентства: витрина, личный кабинет клиента
и админка, из которой ведут заказы, производство, склад, закупки,
бухгалтерию и документы.

Заменяет PHP-сайт, который лежит в корне репозитория. Данные те же -
`scripts/migrate-data.mjs` переносит их из боевой MySQL в PostgreSQL.

Next.js 16 (App Router) · TypeScript · Drizzle ORM · PostgreSQL 17 ·
Tailwind CSS 4 · Auth.js. Разворачивается через Docker Compose за Caddy.

## Разработка

```bash
docker compose -f compose.dev.yml up -d   # база на localhost:5434
cp .env.example .env                      # и заполнить
npx drizzle-kit push                      # схема в пустую базу
node scripts/migrate-data.mjs             # данные из боевой MySQL
node scripts/seed-company.mjs             # реквизиты продавца
npm run dev
```

`AUTH_SECRET` генерируется как `openssl rand -base64 32`. Без
`TELEGRAM_BOT_TOKEN` бот просто молчит - остальное работает. А вот
восстановление пароля без канала доставки работать не может: нужен либо
привязанный телеграм у клиента, либо настроенный SMTP.

## Проверки

```bash
npm run check           # все проверки разом
npm run verify-restore  # база вернулась к состоянию дампа
```

`npm run check` прогоняет то, что легко сломать незаметно: раскрой листа,
сумму прописью в документах, правила загрузки файлов, приёмку по контролю
качества, коды привязки телеграма, редиректы со старых адресов, счётчик
попыток входа и ссылки на смену пароля.

`verify-restore` нужен после ручных проверок в браузере: во время них
приходится временно менять пароли и заводить тестовые строки, и скрипт
показывает, что ничего из этого не осталось в базе.

Отдельно: `npx tsc --noEmit` и `npx eslint src --max-warnings=0`.

## Развёртывание

```bash
docker compose up -d --build
```

Поднимаются три контейнера: PostgreSQL, приложение и Caddy. Caddy сам
получает сертификат Let's Encrypt на домен из `SITE_DOMAIN`, поэтому к
моменту запуска домен уже должен указывать на сервер.

Загрузки клиентов лежат в томе `uploads` и наружу статикой не раздаются:
макеты и документы приватные, их отдаёт приложение после проверки прав.

## Переключение со старого сайта

1. Снять дамп боевой MySQL: страховка перед переносом и то, с чем потом
   сверяется число строк.
2. Заполнить `.env` на сервере: боевые `DATABASE_URL`, `AUTH_SECRET`,
   `SITE_URL`, `AUTH_URL`, `SITE_DOMAIN`, почта, токен бота, Точка.
3. `npx drizzle-kit push` и `node scripts/migrate-data.mjs` - перенос
   данных. Скрипт идемпотентен, его можно гонять повторно.
4. `node scripts/seed-company.mjs` и сверить реквизиты в
   «Админка → Реквизиты»: из них собираются счета и УПД.
5. Поднять `docker compose up -d --build`, проверить сайт по IP или
   временному домену.
6. Переключить DNS на новый сервер.
7. Зарегистрировать вебхук телеграма в «Админка → Телеграм»: у бота он
   один, и до этого шага он всё ещё указывает на старый сайт. Пока
   вебхук не перерегистрирован, старый адрес `/telegram_webhook`
   подменяется на новый обработчик - бот не замолкает.
8. Отправить новую карту сайта в Яндекс.Вебмастер и Search Console.

Старые адреса переезжают сами: `src/lib/redirects.ts` разбирает все живые
пути PHP-сайта - от `/payment_delivery` и `/service?id=7` до закладок
сотрудников на `/admin/order/details?id=14`. Проверяются они через
`npm run check:redirects`.

## Безопасность

Политика `Content-Security-Policy` собирается в `src/proxy.ts`: скрипты
разрешены по одноразовому ключу, чужие рамки - только карта на
«Контактах». Ключ новый на каждый запрос, поэтому страницы отдаются
динамически; они и так почти все ходят в базу.

Частота попыток ограничена в `src/lib/rate-limit.ts` - вход, регистрация,
форма обратной связи, восстановление пароля и привязка телеграма. Счётчик
лежит в базе, а не в памяти: иначе он обнулялся бы при каждом перезапуске
контейнера.

Ссылка на смену пароля хранится в базе отпечатком, а не как есть: утечка
базы не должна означать готовые захваты аккаунтов.

## Чего ещё нет

- оформление заказа на витрине - корзина есть, дальше пока нет;
- журнал действий: таблица `audit_log` заполнена не будет, пока в неё
  никто не пишет;
- рассылки по клиентам (`/admin/messaging` на старом сайте);
- отзывы о товарах: модерация в админке есть, оставить отзыв на витрине
  нельзя;
- выгрузка в 1С - отложена намеренно.
